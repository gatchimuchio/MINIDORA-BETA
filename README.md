# MINIDORA Engine β — 独立抽出版

MINIDORAは、入力から目的に基づく状態駆動、採否、外部表現までを扱うHDS駆動エンジンである。
LLMやチャットボットは応用領域の一つであり、エンジンの定義ではない。

この版は、既存リポジトリの公開ソース414ファイルを保持したうえで、三機構を接続するβ入口と最小限の非退行修正を追加した独立した版である。元リポジトリの履歴や非公開理論を置き換えるものではない。

## 三機構と責任

| 機構 | 公開入口 | 所有責任 |
|---|---|---|
| 入力機 | `HDS入力系.受理` | 原文・出所・文脈の受理、意味変換の一回性、入力束の封緘 |
| ミニドラ本体 | `HDS駆動コア.入力実行` | 目的保持、作用の構成・選択・実行、学習状態、最終採否 |
| 出力機 | `HDS出力系.表現` / `送達` | 採用結果の表現、判断版・失効・送達の管理 |

β入口 `minidora.engine_beta.ミニドラβ実行機` はこの順序を統合する。意味決定・駆動・採否・学習・表現を新たに重複実装しない。外部送達は明示実行であり、`実行()` から暗黙に送信しない。

実行例（**制御された人工作用による配線検証であり、算術能力・一般推論能力の実測ではない**）:

```python
from minidora.engine_beta import ミニドラβ実行機
from minidora.HDS実行主体 import HDS関数作用, HDS作用結果, HDS作用状態

作用 = HDS関数作用(
    "試験処理",
    lambda 状態: HDS作用結果(
        HDS作用状態.成立,
        追加状態=frozenset({"処理済み"}),
        成果=(("結果", "試験完了"),),
    ),
    出力状態=("処理済み",),
)
β = ミニドラβ実行機()
結果 = β.実行(
    "処理を実行",
    案件ID="案件001",
    入力ID="要求001",
    要求状態=("処理済み",),
    追加作用=(作用,),
    成果名="結果",
)
print(結果.駆動.終端.value)
print(結果.表現.本文)
```

入力の識別単位は `(案件ID, 入力ID, 入力版)`。同じ版を再駆動せず、結果は `結果を参照` で取得する。再処理する場合は明示的に入力版を上げる。このβ統合入口の重複抑止・結果参照は**単一実行機インスタンスのメモリ内契約**であり、プロセス再起動を跨ぐ耐久化を保証しない。

## 既存能力の継承

- 既存の `src/minidora` 全公開ソース414ファイルを含む。
- 構文化、選択実行、数量・関係処理、作用供給、学習、非退行、停止、再開、記録等の既存入口を削除しない。
- 選択入力は `HDS駆動コア.入力選択実行`、関係入力は `HDS駆動コア.入力関係実行` 等の既存経路を継承する。β統合入口の `実行` は現時点で**一般テキスト入力向け**であり、全ての専門入口を一つの関数へ統合したという主張はしない。
- 入力・出力側に駆動と独立した第二の学習・判断ループを新設しない。

## 導入・再現

Python 3.11以上。

```bash
python -m pip install .
python -c "from minidora.engine_beta import ミニドラβ実行機; print(ミニドラβ実行機)"
```

最小依存は `SudachiPy==0.6.11` と `SudachiDict-core==20260723`。外部クラウド・検索・送信には別途明示した環境と権限が必要。標準の `minidora` と `minidora-product` コマンドは継承する。

## β版の保証と未保証

- 保証範囲：三機構の基本的な接続、入力版の一回性、最終採否の保持、出力表現の明示分離、関連回帰試験で検証された停止・依存・再開・非退行。
- 未保証範囲：任意の自然言語要求を自律的に解けること、任意領域での正答率、クラウド上の実環境互換、全公開テスト・ベンチマークの完全合格、プロセス間の耐久的冪等性。
- 歴史的なGPQA等の評価値は、異なる日付・構成の観測であり、このβ版の新しい性能実測値ではない。
