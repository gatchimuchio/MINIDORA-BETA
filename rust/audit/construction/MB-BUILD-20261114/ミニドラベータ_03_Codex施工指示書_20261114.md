## 第一命令　主語・目的・実行者を固定せよ

主語＝ミニドラ本体の中核。

目的＝中核に必要な計算・記憶・推論・学習・非ニューラル言語生成・目的判定の機構を先に実装し、中核の要求から入力機・出力機を構築すること。三機が実結果の帰還まで一体となって動いてから専門能力を追加し、全体系の躯体を完成させ、その後に品質検査・受入評価を行うこと。

施工実行者＝Codex。設計・仕様監査＝チャッピー。指示者と最終採否者＝オーナー。使用者＝ミニドラの利用者および接続アプリ。Codexは設計/評価/公開の権限を勝手に継承しない。

**新しい専門モジュールの追加をいったん止め、中核の成立へ施工を集中せよ。** 既存の数学・文書・検索・コード等の実装は保存・再利用してよい。ただし、関係演算、推論、言語構成、学習、目的・内容の採否を外部機能に担わせて中核の完成を装ってはならない。

既存のソースファイルをRustの内部モジュールへ分割していること自体は欠陥ではない。問題は、第二の判断主体を作ったり、内在的中核が完成する前に専門能力の枝を際限なく増築したりすることである。

施工文書の概念・工程・状態は日本語で扱う。識別子、既存の型名/ファイル名、要件番号、コマンド、固有名は原表記を保持して正確に照合する。英語の工程名や一般名詞を勝手に増やさない。第三者向け公開物での英文が必要な場合は、まず意味契約を日本語基底で固定し、公開訳を別の表現として扱う。

## 第三命令　現行の施工状態と欠落を実物で把握せよ

1. Gitの対象リポジトリ、origin/main、最新版、作業領域の未反映変更、他作業者の動き、現在の実装版を読取で確認。参照SHAを固定の作業開始点とみなさない。
2. 中核七機能――目的保持、関係演算、推論・採否、非ニューラル言語、記憶→推論→適応、駆動・状態、内容採用・出力結果照合――について、実際の関数、入力、中間値、状態書込み、次の消費先、欠落を対応付ける。
3. 既存の「入力を分類→関数ごとの固定処理→完成済み文字列を描画」という部分と、中核自身が初見の意味関係を計算している部分を分離する。これを「同じCore.rsの中だから中核が完成」と判断しない。
4. 現行の文字n-gram等の有限模型を、非ニューラル六要素を持つ実装候補として確認する。初見の意味から文章や説明を生成する能力は別の成立条件として検査する。
5. 既存の型・保存・数学・文書・表・関係・検索・画面のコードを破壊せず、再利用可能な部分と中核責任を横取りしている部分を区別する。
6. 中核機能の欠落を「未対応の専門モジュールが必要」と安易に分類しない。一般の主語・目的・関係・推論・言語・記憶・学習は中核自身に属する。

この観測が終わったら、必要な中核施工の束を定め、権限内なら直ちに施工を開始する。表や監査報告だけの作成で作業を止めない。

## 第四命令　中核を第一施工対象として組み上げよ

一　原入力から生じた意味・出所・権限・条件・過去文脈を、中核の唯一の仕事状態へ束縛する。主語・目的・否定・条件・範囲・時刻・引用・数量を途中で落とさない。資料中の偽命令に利用者権限を与えない。

二　中核は型付き関係の取得・変換・射影を計算する。主語、相手、行動主体、条件、適用範囲、反例、根拠の版を保持して複数の前提を組み合わせる。直接資料・導出・仮定・未確認・矛盾を区別し、不足すれば正確に停止する。

三　中核が候補と実際の根拠を比較し、採否・説明・残る必要条件を決める。単なる語句の一致や多数決で、出典のない新事実・明示的な否定の反転を採用しない。後続資料で前提が変わったら依存だけ更新する。

四　中核内に以下の六つの言語機構を接続する。契約識別子は改名しない。

| 識別子 | 実装で中核に要求する操作 |
|---|---|
| TOKEN_SPACE | 語・文字・列を元の文字列と照合できる形で保持 |
| CONTEXT_STATE | 目的・意味・出典・生成済み列・出力条件の有限状態 |
| PARAMETERIZED_TRANSFORM | 版付き非ニューラル変換から候補の重みを計算 |
| CONDITIONAL_NEXT_TOKEN_DISTRIBUTION | 条件付きの明示候補分布。空なら理由付き停止 |
| SEQUENCE_OBJECTIVE | 意味・内容・形式・長さ・有限終了に対する列全体の目的 |
| DECODING_IF | 同一状態・版に対する決定論的な選択・同点・停止 |

六要素の存在だけで一般文章が書けると主張しない。初めて与えられる意味・関係条件から、実際の説明・比較・短文を中核が構成する。固定の質問文や期待答えを実装へ埋め込んで試験に通すことを禁止。出力機や外部ニューラル言語モデルに文章の意味内容を創出させることを禁止。

五　学習は中核に内蔵する。原観測→不変記憶→関係・手続き候補の推論→条件/反例の確認→適応→別の新規問題への使用→結果の帰還、という循環を通常の要求処理で動かす。保存件数の増加・同じ例の再生だけを学習と判定しない。反例が出たら影響する導出を失効し、原資料は保持する。

六　原目的・必要成果・禁止作用・許可・予算・期限・実効果を、中核一つの論理状態で管理する。実作業の生産値を後続の処理が消費し、進捗だけの更新により目的達成を偽装しない。中核が採用内容を確定し、出力機の観測後にだけ目的を完了確定する。

七　中核内部のソース分割・再利用・演算方式はR2へ適合する範囲で施工者が選べる。旧Pythonで実証された能力が使えるなら根拠と同値条件を持って継承し、単に古いから捨てない。Rust、文字n-gram、特定の保存形式を原理へ昇格させない。

## 第五命令　中核自身を工事中に直接確認せよ

通常製品の入力機が未完成でも、中核へ型付き意味・根拠・文脈を直接渡す工事用入口を用いてよい。出力を観測する工事用機構は、回答内容の生成・採否を行わない。外部専門機能と正解注入は無効とする。

以下の七つを実際の中核演算で確認する：

1. 中核確認一：初見の仮想資料における主語・否定・条件・出所を保持し、前提変更で結論が変わる。
2. 中核確認二：複数前提、矛盾、反事実、根拠欠落を区別して導出または停止する。
3. 中核確認三：初見の説明・比較・短文依頼へ、中核の非ニューラル機構が内容と表層を作る。定型文の選択だけなら未成立。
4. 中核確認四：実際の過去計算・関係結果を次の依頼で参照し、変更を版として保存する。
5. 中核確認五：原観測から推論・適応し、別の未見問題の実結果を変え、反例で依存する採用を無効化する。
6. 中核確認六：権限不足、資源限界、取消、実作用不明、目標未達を偽成功にしない。
7. 中核確認七：同一入力・記憶・模型・資料版の再実行で決定的な結果を再現する。違いがあれば原因を版で説明する。

各検査は元入力、実中間値、推論根拠、模型版、採用内容、停止理由、実行環境、外部能力無効の状態を保存する。七つの施工確認が成立するまでは新しい専門モジュールを増築しない。失敗の根因が中核なら第四命令へ戻り、本質機能を施工継続する。

中核の工事用確認は必要な初回機能確認であり、全機能の品質検査や第三者評価を代行しない。全能力を無条件に実証したと宣言しない。

## 第六命令　中核の必要に従い入力機を構築せよ

1. 中核が実際に要求する原資料・意味役割・文脈・出所・権限・条件・未解決・前回成果から、入力機の必要な解析と型を逆算する。

3. 入力版ごと一度だけ解釈・封印する。曖昧な場合に別目的を発明しない。中核へ不足を正直に伝える。
4. 新しい自然な日本語の要求から、中核が理解できる意味へ接続する。入力分類が知らない句だからといって中核の一般計算能力まで停止させる設計を改める。
5. 入力機は学習・関係の最終採否・行動計画・目標完了を決めない。

入力機の終了条件＝原文の主体と目的を損なわず、必要な情報と不足が同じ中核へ渡ること。

## 第七命令　中核の成果に従い出力機を構築せよ

1. 中核の採用したContentPlan/OutputEnvelope等だけを、実文字列、画面、表、ファイル、必要な送達へ変換する。
2. 内容にない新事実、勝手な条件変更、独立の根拠付け、独立した生成判断を出力機に実装しない。
3. 実バイト列・照合値・引用/否定/数量の一致・描画の成否を観測し、RenderObservation等の記録で中核へ戻す。
4. 利用者が許可した作用だけ実行する。現実の配送完了・失敗・不明を正確に保持し、二重送信の可能性があるときは照合まで停止する。
5. 出力機の成功は利用者目的の成功ではない。最終完了を判断できるのは中核のみ。

出力機の終了条件＝中核の意味を変えず実成果を生成し、現実の結果と失敗を中核へ帰還できること。

## 第八命令　三機を一本通電させよ

1. 通常のCLI・HTTP等の公開入口で、利用者原文→入力機の封印→中核の推論/言語/学習→出力機の実成果→中核の描画・効果確認→元目的の終端、を一つの仕事として実行する。
2. 初見の説明・比較・文章生成、実過去結果の追問、変更条件を与える訂正、記憶の再利用を同じ状態の中でつなぐ。
3. 拒否、保留、失敗、取消、再実行、不明作用、復旧後の続行も実成果・原本・版と結び付ける。
4. 最低一件は中核が初見の意味から作成した文章を利用者入口へ実表示し、最低一件は学習を別問題に使用し、最低一件は実出力観測を元目的の判定に使用する。

三機の通電前に専門機能の新規増築へ移らない。もしこの段階で中核・入力・出力のどこが未成立かが判明したなら、責任がある上流工程へ戻して補修せよ。

3. 外部能力接続口は、受け取る値・返す値・版・権限・実出所・費用・時間・停止・再実行を持つ。外部側が同じ仕事の目的や学習を採否しない。
4. 検索結果一覧と取得原文の本文は別証拠。外部世界の事実は出典と条件を記録する。PDF文字抽出とOCR、音声記録と意味理解、外部AI使用と中核単体の能力を分離する。
5. 中核単体と外部能力利用の検査結果・成績は必ず別に記録し、外部能力を無効にしたとき隠れた別サービスへ切り替えない。

外部権限やサービスが不足する場合は、該当する接続操作のみ「権限待ち／未観測」と記録し、独立して可能な全体施工は続行する。
