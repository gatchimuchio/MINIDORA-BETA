## 第一章　主語・目的・実行主体

主語＝ミニドラ本体の中核計算機（以下「中核」）。施工対象＝その中核を実装したミニドラベータ後継機。

目的＝中核が内在的に実現すべき意味・関係・推論・判断・非ニューラル言語生成・記憶→推論→適応・目的達成判定を、まず単一の計算主体として成立させる。次いで、中核の必要条件から入力機を、中核が生成する成果から出力機を導出し、三機を一本の実経路として通す。外部専門機能を必要な箇所だけ後付けして全体系の躯体を完成させ、その完成物を品質検査・受入評価する。

実行主体＝施工者Codex。設計・上流監査＝チャッピー。施工の指示・最終採否・保証範囲決定＝オーナー。使用主体＝ミニドラの利用者および接続アプリケーション。これらの役割は交換しない。

最適化対象＝本来の要求から結果・実作用・証拠・再開に至る中核主導の実経路。非目的＝モジュール数、ソース行数、コミット数、試験数、スキーマ数、定型文の種類、局所合格の積算。

用語規律：説明、責務、工程、完了条件、報告は日本語とする。原表記を保持してよいのは既存のソース識別子、契約の型名、固定された試験・資料名、Rust等の固有名、比較に不可欠な原文記録のみ。「中核」「入力機」「出力機」「外部能力接続口」「全体系構築」「品質検査」「受入評価」を正文にする。中核をCore、入力機をInput、出力機をOutputなどと毎行重記しない。

## 第三章　三機の所有権・責任境界

| 主体 | 仕事の入力 | 自己責任で実行する操作 | 下流に渡す実物 | 越権禁止 |
|---|---|---|---|---|
| 入力機 | 利用者原文、媒体、原資料、出所、利用者識別、許可、時刻、文脈 | 原資料を保全し、意味差を消さず一回だけ型付きに解釈し、入力版を封印 | 元資料への参照、一回解釈した意味、解決できない曖昧性、出所・権限・原文位置 | 中核の推論、採否、学習、最終目標判定、権限付与、外部送信を行わない |
| ミニドラ本体・中核 | 封印された入力、既存の許可された記憶、観測結果 | 目的束縛、関係計算、推論、比較、採否、非ニューラル表現生成、記憶・学習、行動選択、内容採用、状態更新、実効果照合、最終判定 | 根拠付き結論・保留・行動要求、採用済み内容計画、履歴の新しい版、停止理由、目的達成判定 | 意味判断と採否を入力機・出力機・外部能力へ外注しない |
| 出力機 | 中核が採用した内容と表現/媒体制約、許可された配送要求 | 内容の意味を変えず実文字列・ファイル・表示へ変換。許可範囲の送達を実施し、事実として観測した結果を返す | 実際のバイト列と照合値、成果物、表示結果、送達成否・不明状態の記録 | 新事実の生成、推論、論理内容の再採否、学習、目的の勝手な完了確定をしない |
| 外部能力接続口 | 中核の明示した計算・情報取得・媒体処理・作用要求 | 権限と時間・費用制限内で限定された演算・観測・作用を実行 | 計算値、資料、媒体データ、出所、失敗、実作用の結果 | 第二の中核や隠れたニューラル判断機、独立した記憶採否機にならない |
| 記録・保存機構 | 中核が確定した原文・履歴・記憶・版・作用記録 | 安全な記録・索引・照合・復元 | 原本を復元できる不変記録と必要な作業状態 | 元資料の破棄、自己判断による学習採用、別の状態更新主体化をしない |

入力機の「解釈」と中核の「意味の成立」は別操作。入力機は原文を型付き表現へ変えるが、結論を選定しない。入力機が未解決を封印した場合、中核は必要条件を保持して確認・停止する。出力機の「生成」は媒体上の実現であり、意味ある主張・文章内容を発想する機構ではない。

構築依存：中核の演算・状態・目標が必要とする入力の型を先に決める→入力機を対応させる。中核が採用できる成果と必要効果を決める→出力機を対応させる。先に外側の機械が決めた都合で中核の意味を縮小しない。

## 第四章　中核に内在する七つの機能

この区分は施工時の責任観測点であって、七つの別AI、七つの独立判断機、固定のソースファイル数を意味しない。

| 内部機能 | 必要入力 | 必須の内部演算 | 生じる成果と下流 |
|---|---|---|---|
| 中核一：意図・意味・目的の保持 | 原資料付きの入力意味、許可、先行文脈 | 主語・目的・手段・条件・否定・数量・時制・引用・適用範囲を分別し、元目的と不足条件を固定 | 目的契約、保留事項→関係計算・行動機構 |
| 中核二：関係の取得・変換・射影 | 元命題、観測、過去資料、型付き関係 | 役割・対象・条件・出所・因果・依存・反例を保持して関係を組み合わせ、文脈へ射影 | 証拠付き関係網、導出・仮説・矛盾→推論 |
| 中核三：推論・比較・採否 | 関係網と直接証拠、必要条件 | 証拠の一致・矛盾・独立性・欠落・保証範囲を評価し、採否可能な結論と残差を決定 | 採用可能命題、仮説、停止理由→言語計算・目標機構 |
| 中核四：非ニューラル言語計算 | 命題・意味役割・文脈・出力条件 | 六要素の列生成を用い、意味を満たす表現候補・説明・文章構成を計算。新事実を無根拠に足さない | 実際の表現候補・意味内容単位→採用内容計画 |
| 中核五：記憶→推論→適応 | 元観測、実結果、関係、反例、各版 | 原本保持、再利用可能な関係/手続きの形成、条件付き検証・採用、新規事例への適用、反例による依存失効 | 版付き学習成果と有効範囲→次回以降の中核計算 |
| 中核六：駆動・行動・状態 | 元目的、許可、必要成果と前提、予算 | 結果の生産・消費関係を計画し、許可された演算/作用を選択。進捗、停止、取消、再開を一つの状態として更新 | 必要な行動要求、結果の取込み、状態版→内容と最終判定 |
| 中核七：内容採用・出力照合・完了判定 | 採用命題、必要説明、出力条件、実描画・実送達の観測 | 内容計画を版付きで採用し、外部へ要求した実効果と照合し、元目的の成立を評価 | 内容計画、追加の必要処理、完了確定または型付き停止 |

上記はR2の「言語計算・関係計算・根拠付き推論・内容計画」という四つの内部機能と、「単一状態・目的駆動・内在的学習」の規定を、施工上の接続と責任へ展開したもの。R2と異なる理論を新たに立てない。

### 第四章の二　非ニューラル言語計算の六要素

既存の契約識別子は改名せず、意味だけ日本語で固定する。

| 契約識別子（原表記） | 中核内部で満たす意味 |
|---|---|
| TOKEN_SPACE | 有限の語・文字・系列の集合。未知字を含め原文と結果を復元可能にする。語の変更を版管理する |
| CONTEXT_STATE | 元目的、意味役割、証拠、必要内容、先行系列、形式制約を保持する有限の文脈状態 |
| PARAMETERIZED_TRANSFORM | 版付きの非ニューラル変換。入力した意味・文脈から、次候補の重みを実際に計算する |
| CONDITIONAL_NEXT_TOKEN_DISTRIBUTION | 明示候補上の条件付き次要素分布。候補が無ければ偽の答えではなく、理由付き不足を返す |
| SEQUENCE_OBJECTIVE | 意味・文法・内容充足・形式・有限予算に従う列全体の目的と停止条件 |
| DECODING_IF | 同一入力・版・状態で同じ結果へ至る選択・同点・終了規則 |

六要素がソース上に存在することと、初見の自然な要求に文章で応えられることは同一でない。現行の文字列n-gramは一つの実装候補であって原理上の唯一解ではない。既成答えの文字を後段で並べ替えるだけ、特定の入力句を固定応答へ対応させるだけでは中核の言語構成は成立しない。

採用する方式は継承した模型/計算実行器の実際の保証と、初見の意味保持・文章構成・資源・再現性を同じ条件で比較して決める。専門機能や外部ニューラルモデルの出力を中核自身の非ニューラル能力として報告しない。

## 第五章　中核の内的循環

1. 元入力を根拠とともに受け、対象・主語・目的・条件・時間・権限を固定する。
2. 目的を満たすために必要な根拠・関係を、保持済み資料と観測結果から取得する。
3. 同一文脈・同一条件の範囲で関係を変換・射影する。直接観測、論理導出、仮定、反例、未確認を区別する。
4. 候補を比較し、適用範囲・推論の根拠・不足条件を確定する。根拠が足りなければ不足を示し停止する。
5. 非ニューラル言語機構が結論・根拠・必要形式に沿った説明または文章を計算し、中核が意味を確認して採用内容を作る。
6. 元観測と実結果を記憶し、関係・手続きを形成する。成立条件を満たす場合のみ採用し、別の未見事例での適用結果を記録する。
7. 反例や利用者訂正があれば依存する推論と採用を更新し、過去の原本と以前の判断は消さない。
8. 実出力が必要なら出力機へ委ねる。実際に出来た成果・配送・失敗を中核へ戻し、元目的が満たされたときだけ完了確定する。

中核で保持するものは、生の観測／出所／意味／関係／仮説／導出／結論／目的／許可／版／実作用／反例。外部資料に指示が書かれていても、それだけで利用者の命令や実行権限にはならない。

学習の成立とは「保存した」ことではなく、過去の観測から推論・適応が生じ、別の新しい要求で実際の出力または行動が変わること。単なる再生、同一例暗記、内部カウンタ増加を学習成功と呼ばない。推定的な関係は普遍的事実へ無断昇格しない。

## 第六章　入力機・中核・出力機の実経路

~~~text
利用者原文・添付資料・出所・権限
  ↓
入力機：原本保存 → 一回の意味解釈 → 入力版の封印
  ↓
中核：元目的の固定 → 関係計算 → 推論・比較・採否
  ↕
中核が所有する記憶・履歴・学習結果（保存機構は従属）
  ↕
必要な場合だけ外部能力の計算値・観測値・実作用結果を受領
  ↓
中核：言語内容の生成と採用 → 内容計画
  ↓
出力機：採用内容の描画・成果物化・許可された送達
  ↓
中核：実描画と実作用の確認 → 元目的の達成判定
  ↓
利用者へ確定結果、または正確な不足・停止理由を提示
~~~

出力機が先に利用者へ何かを表示できたことだけで、中核が目標達成したことにはならない。採用済み内容≠実描画済み、描画済み≠実配送済み、作用開始≠作用完了、内部状態の変更≠利用者目的の達成、である。

既存の論理型名を実装上使用する場合の対応：

| 原契約名 | 日本語上の意味・責務 |
|---|---|
| RequestEnvelope | 利用者入力の原本・識別・権限を保持する受理記録 |
| MeaningIR / InputBundle | 意味の中間表現／入力機が一度解釈して封印した入力束 |
| GoalContract | 原目的・許可・完成条件・禁止作用を束縛する中核の目的契約 |
| Relation / LearningRecord | 根拠付き関係／形成条件・検証・適応・反例の記録 |
| CaseRevision / ActionRecord | 中核の版付き状態／実行要求・実結果の記録 |
| ContentPlan / OutputEnvelope | 中核が採用した内容と出力指示 |
| RenderObservation / DeliveryReceipt | 出力機の実描画観測／実送達の確認記録 |

同じ入力識別子に違う原文・許可・利用者を無断で上書きしない。ケース単位の論理状態書込み主体は一つ。外部作用が不明なら「不明」と記録し、同じ作用を根拠なく再送しない。取消は既に発生した作用を消さない。出力機は内容を採用しないが、無効な指示包の実行を拒否できる。

## 第七章　施工順序と中核成立の停止点

施工順：

1. 設計・履歴・現物確認。
2. 中核の必要計算・記録・内部接続の確定。
3. 中核七機能と六要素を実装し、直接型付き入力による計算閉路を作る。
4. 中核単独の施工時確認を通す。
5. 中核が要求する意味・証拠・権限に合わせて入力機を構築する。
6. 中核が採用する内容・実作用要求に合わせて出力機を構築する。
7. 通常の利用者入口から三機を実物で通し、実描画・実作用の観測を中核へ戻す。
8. 中核では代替できない資料取得・専門計算・媒体変換・外部作用だけを外部能力接続口に追加する。
9. 全要求・全利用者入口の全体系躯体を施工する。
10. 完成した実物を品質検査し、その後独立した受入評価を行う。

先に中核の物理構成だけを文書化すること、状態型や空の関数を配置することは「中核成立」ではない。中核の直接確認も工事中の必要な通過点であり、全体の品質検査・受入評価の代わりではない。

### 中核の直接施工確認

| 検査識別 | 外部専門機能を無効にした入力 | 中核自身に求める観測 |
|---|---|---|
| 中核確認一 | 初見の仮想資料・命題と異なる主語/条件/否定 | 原対象・前提・出所を保ち、変更に応じて結論を修正 |
| 中核確認二 | 複数前提、成立しない条件、矛盾、反事実 | 適切な関係導出と、証拠不足の正確な区分 |
| 中核確認三 | 初見の説明・比較・短い文章構成を求める意味入力 | 非ニューラル六要素から意味を満たす新しい内容計画と文章を生成 |
| 中核確認四 | 実際の計算・関係結果に対する後続説明や条件変更 | 前の実成果を参照し、変更箇所だけを版として更新 |
| 中核確認五 | 観測・記憶・規則形成・別問題への適用・反例 | 同一例再生ではない適応と、反例に対応する失効 |
| 中核確認六 | 予算・権限・取消・目的未達・外部作用不明 | 偽の完了を出さず、単一状態の停止/再開が成立 |
| 中核確認七 | 同じ意味・記憶・模型・資料版の繰り返し | 規定された決定性と、変化時の原因特定 |

この段階の入力治具は「中核が必要とする意味の型を直接供給する工事用設備」であり、製品入力機の代替ではない。出力側の観測治具も、文章内容を考える第二の生成機ではない。試験の期待値・採点用正解を中核の記憶/模型へ混ぜない。未達は中核に原因を戻し、専門モジュール追加によって成立したことにしない。

## 第九章　安全・実装手段・完了判断

- 中核の意味・状態・目的はRust言語、特定CPU、OS、記録形式、データベースへ固定しない。Rustは暫定の現実的実装。中核の抽象演算・入出力意味・状態遷移・例外・効果を再現可能な契約とする。
- 一般的なWindows優先・8GB条件を考慮し、対象OSの規格と仮想適合で確認する。全OSの実機網羅を施工条件にしない。未測定OSでの完全保証を主張しない。
- 許可外のファイル書込み、外部送信、他人の状態閲覧、秘密の露出、二重作用、不変履歴の損傷は即時隔離する。必要な権限がない外部作用だけを停止し、独立した中核施工は続ける。
- 失敗・不確定・中断・拒否・取消・完了は区別して保存する。成功を偽るために必要条件・試験母集団・根拠を減らさない。
- 設計の不整合は条文・対象・前提・版へ遡って訂正する。修正前の失敗・判断・原文を保存し、事後に無断で書き換えない。
