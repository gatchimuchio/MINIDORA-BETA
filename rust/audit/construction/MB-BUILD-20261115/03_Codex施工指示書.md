## 第4命令　七ゲートは**成功述語**を判定し、偽PASSを禁止せよ

工事用の型付き意味入力と非判断性の出力観測治具を用いて、七ゲートを実行せよ。入力機・出力機・外部専門機能が未完成でも、中核自身の成立だけは直接実証できる。ただし治具に中核の判断・新意味生成・学習を実装してはならない。

**ID衝突禁止：** ここでの中核施工ゲートは`CORE-G01`〜`CORE-G07`と記す。既存R2の93要求にある`C01`〜`C13`は外部根拠・検索の別対象。両者の合否・母集団・根拠を同一IDで記録するな。

各ゲートの証拠は次を同一版で結べ。

要求述語、事前に用意していない新規原入力、適用条件、Core内の関数と入力値、実際に生成した中間値と依存根拠、次consumer、採用/停止、観測時の版、PASS/PARTIAL/FAIL/NOT_RUN/BLOCKED_AUTHORITY/UNKNOWNの判定。観測内容を元要求と比較し、**通過したテスト名称ではなく成立述語そのものを評価せよ。**

- CORE-G01：異主体・否定・条件/範囲を変更すると、同一の根拠対応を保って中核の実結果が変わる。
- CORE-G02：複数の新前提を組み合わせ、適用条件不足・矛盾・反事実と成立した導出を中核が区別する。
- CORE-G03：**完成された主張文・説明文を渡さない。** 原子的命題/関係/出所/出力目的を入力し、中核が新しい内容計画と説明・比較・短文を生成し、K7が採用して根拠と照合する。元文をすべて一回ずつ表示し接続句を付けるだけならPARTIALまたはFAIL。六要素やn-gramの存在のみではPASSでない。
- CORE-G04：過去の実計算/関係を次の依頼の実値として消費し、訂正による新版を使用する。過去の原文と結果を残す。
- CORE-G05：R2の**証明保存型合成**（型・条件・変数・依存の検証、回復可能な証明）または**観測起点の仮説形成**（事前の経験的採用契約のない仮説はHYPOTHESIS_RETAINED）について、同じ**工事用直接中核入口**の学習前後を測り、未見の別問題の実結果/推論経路が変化することを実証。領域外例と後続矛盾で旧採用を正確に失効。通常利用者入口は三機接続後T02で再実証。単なる規則の入力/再生、無根拠な経験的採用ではPASSとしない。R2が認める正当な証明保存型合成を独断で除外するな。
- CORE-G06：権限・予算・取消・不明効果・必須成果不足で偽COMMITしない。中核一つの状態と復帰条件を保つ。
- CORE-G07：同一意味・記憶・模型・資料版で計算・生成・採否の同一性が成立し、条件/版の差なら原因を記録する。

**全七件PASSという明示述語が真の場合だけ、第5命令の入力機施工へ移れ。** 一つでもPARTIAL/FAIL/NOT_RUNならその根因をK1〜K7に戻して施工を続けよ。正機能に関係ないテスト件数増加で穴埋めするな。「七観測実施済み」や「報告生成済み」を終了条件にしてはならない。

## 第5命令　入力機は三機接続のため必要な範囲で先に通せ

中核で実際に使用した意味契約・出所/条件/否定/文脈/権限を、既存InputBundle/MeaningIRへ逆投影せよ。初見説明/比較、記憶からの追問・訂正、曖昧/不正/権限不足の代表的な日本語入力を、通常の入口で封印し同じ中核へ渡せ。原文とsource span、正規化との差、actor、版、出所を保持せよ。

入力機が学習・最終採否・実行計画を決めることを禁ずる。未知構文は型付き未解決へ保留し、元目的を別目的に改変するな。

**入力機の工程終了条件＝上記代表入力がK1〜K7の実演算へ届き、原文の主語/目的・意味と許可の不変が確認できること。** 自然文の全形式、英語文法全体、NFKC/spanの全組合せ、長文/全媒体は後続93要件の全体系施工に残し、ここで無期限に局所充実させるな。既存対応の退行を意図的に許してよい意味ではない。

中核ゲートが未成立なら入力機増築を停止し、Coreの不足へ帰還すること。現存するB17〜B30のソース/履歴を無断で消さず、施工した価値だけ保全せよ。

## 第6命令　出力機は中核採用結果を実物にせよ

K7のContentPlan/OutputEnvelopeだけを受け、少なくとも実文字列をCLIまたは既存HTTPで実描画し、文字列/バイト・数量/否定/引用/出所の整合値、RenderObservation、必要ならDeliveryReceiptを返せ。Coreに実描画と作用確認が戻る経路を先に作れ。出力機に新しい意味・結論・学習・最終成功判定を持たせるな。

実送達は許可範囲でのみ行い、NOT_REQUESTED/PREPARED/ATTEMPTED/CONFIRMED/UNKNOWN/FAILED/CANCELLEDの状態差を保持。実行不明なら安全に停止・照合して二重送信しない。

終了条件＝中核が採用した意味と現実の実出力が照合でき、結果を中核が消費した。文書/音声/画像等の全媒体網羅より、まず三機の実結果帰還を優先せよ。

## 第7命令　三機を一本の**通常利用者経路**として通電せよ

工事用直接Core入口だけでは不可。実際のCLI/HTTP等の公開入口で、原文→入力機封印→中核推論/言語/学習→内容採用→出力機の実成果→中核のreceipt照合→元Goalの終端まで、同一のcase・主体・版を保って実行せよ。

必須通電：

1. T01：初見の意味依頼から新しい説明/比較/短文を中核が作成し、利用者へ実表示、RenderObservationを中核が照合。
2. T02：記憶した観測を後続未見の別問題に適応して実結果が変わり、利用者へ実表示。反例・訂正による履歴と採否更新も示す。
3. T03：描画・許可作用が確認できればGoal条件に従い完了、未達/拒否/不明/取消ならCOMMITせず正確に停止/保留し、中核へ効果を帰還。

通電時の障害は主体を分けて根因工程へ戻せ。中核の未成立を入力の問題、入力の意味喪失を出力の問題、出力の実効果不明を中核の推論能力の問題と誤分類するな。三件実成立までは新専門能力を増築するな。空のHTTP 200、定型挨拶、テスト用の別API、状態型の存在で代用するな。

## 第13命令　工程判定と報告を簡潔に固定せよ

報告の必要項目：対象repoとBASE/FINAL HEAD、今回の許可範囲、現在工程とゲート状態、元目的、対象要件、変更前の実不足、施工したproducer→consumer、実入力/中間値/採用結果/出力帰還と版、実際に行った限定確認、安全/権限、残るPARTIAL/FAIL/NOT_RUN、次に接続する実consumer。

次の区分を厳守せよ：

| 状態 | 判定対象 |
|---|---|
| CODE_PRESENT | コード/型が存在するだけ |
| CORE_WIRED | 中核内の実計算経路が接続されている |
| CORE_GATES_PASSED | CORE-G01〜CORE-G07の**成立述語全件PASS** |
| THREE_MACHINE_WIRED | T01〜T03の通常三機経路実成立 |
| SYSTEM_SHAPED | 全必須正機能が一つの後継躯体に接続 |
| QC_SCOPED_PASS | 固定版/対象母集団の体系的品質検査に合格 |
| QA_SCOPED_RESULT | 独立評価の成立/不成立/未観測が区分された |
| OWNER_RELEASE_DECISION | オーナーが別途公開/配布/保証を許可 |

一つ前の状態やPASSテスト数から次の状態を推定するな。誤った工程移行が見つかれば、移行済みの履歴や既存コードを破壊せず、**ゲート判定だけを実証拠に基づいて訂正し、欠けた根因の施工へ復帰**せよ。

**最終命令：ミニドラベータの主語は唯一の中核。まず中核の本質能力を実計算として成立させよ。次に必要な入力機・出力機を実接続し、三機を通常入口から一体通電させよ。専門能力を後付けして全体躯体を一度で完成させ、その現物に対してQC、次にQAを行え。偽PASS、局所最適化、工程のすり替えを許さない。**
