## 01 主語・目的・責任主体

- 主語＝ミニドラベータの**唯一の中核計算機**。製品の入口・言語・外部能力・モジュール・試験・施工記録を主語にしない。
- 最初の目的＝中核が、意味と目的の保持、関係計算、根拠付き推論と採否、ネイティブ非ニューラルの意味・言語生成、記憶→推論→適応、行動/停止/状態、成果の採用と実結果に基づく目的判定を、自身の状態・責任で行う実機構を完成させる。
- 次の目的＝中核に必要な入力契約から入力機を、採用済み内容と作用契約から出力機を構築し、通常入口から「入力→中核→出力→中核への実結果帰還→利用者目的の終端」を一本通す。
- 最終施工目的＝必要な専門能力と93件＋発見要件を三機に接続し、先に**全体系躯体**を完成させる。その完成版に対して初めて体系的な品質検査（QC）を実施し、次に独立の受入評価（QA）を行う。
- 非目的＝ソース/型/機能/モジュール/テスト/コミット数の増加、局所PASSの積算、既存LLMの名称争い、簡単な定型例に対する見かけの成功、論理的未成立を停止処理だけで覆うこと。
- 指示者＝オーナー。設計者＝チャッピー。施工者＝Codex。使用者＝外部利用者。製造物の保証・公開採否と実施工・設計・指示を混同しない。

4. 原入力、出所、根拠、利用者、許可、条件、否定、版、時間、外部効果は対応を保ち、未解決/未観測/仮説を真実や完了へ昇格しない。

7. Rustは暫定施工媒体。抽象計算・状態・入力/出力・停止・効果・再実行の意味はOS・CPU・ABI・特定言語・データベース・記録形式に依存させない。将来AICompiler等へ実装を交換する場合は別途、契約適合を確認する。

## 03 三機の契約と一方向の責任

| 機械 | 入力契約 | 内在する操作 | 生産物 | 禁止する操作 |
|---|---|---|---|---|
| 入力機 | 原文/原バイト、媒体、資料、利用者、許可、文脈、出所 | 原文保存、出所と位置保持、意味の一回解釈、曖昧・未知の明示、入力版の封印 | RequestEnvelope→MeaningIR/InputBundle | 目的の再定義、関係の最終採否、学習、目標完了、外部作用 |
| 唯一の中核 | 封印入力、版付き記憶/観測、目的/権限 | 関係演算、推論・判断、学習、ネイティブ言語生成、内容採用、行動計画、単一状態更新、結果照合 | GoalContract、関係/根拠、ContentPlan/OutputEnvelope、ActionRecord、停止・再開状態 | 入力/出力/外部能力へ本体の最終判断を委譲 |
| 出力機 | 中核が採用した内容・媒体/配送条件、許可 | 内容を変えない描画・ファイル化・許可された送達、実結果観測 | 実文字列/ファイル、RenderObservation、DeliveryReceipt | 新事実の考案、独自推論/採否、目的完了判断 |
| 専門接続口 | 中核発行の型付き依頼、作用分類、許可/予算 | 限定された計算・読取・媒体変換・許可された実作用 | 計算値/原資料/失敗/実効果の証拠 | 原目的の変更、独立学習と採否、無断副作用 |
| 保存器 | 中核採用済み状態・不変原本 | 版管理、履歴保持、照合、復旧 | 不変記録・索引・復元状態 | 記録器自身による意味判断・目標達成 |

通常実経路＝利用者原文→入力機で一回の解釈・封印→中核で目的・根拠・関係・推論・採否・学習・言語内容を計算→必要な外部値を取得し中核へ帰還→中核で内容計画を採用→出力機で実バイト/実作用を生成→出力観測を中核へ帰還→元の目的を中核がCOMMIT/SUSPEND/FAIL/REJECT/CANCELの適切な状態へ遷移。

状態保証：ADOPTED≠RENDERED≠DELIVERED≠GOAL_COMMIT。外部作用のATTEMPTED≠CONFIRMED。UNKNOWNを勝手に成功・再送許可へ変えない。入力の一回解釈は入力版に対する一回であり、原文変更/訂正は新しい版により記録する。ケース単位の論理writerは中核一つ。

## 04 中核の内在的要素と接続

下記は責任を観測する七領域であり、七つのAIや七つの独立したRustモジュールを指さない。

| 中核領域 | 実入力 | 必要な実演算 | 実出力・下流の消費者 |
|---|---|---|---|
| K1 主語・目的保持 | 意味入力、原文の照合参照、文脈、権限 | 主語・目的・手段を分離し、条件/否定/時制/引用/根拠/範囲を固定 | 目的契約と必要条件→K2/K6 |
| K2 関係計算 | 根拠命題、観測、型付き関係 | 関係の取得・変換・射影、同一性・依存・矛盾・反例を追跡 | 根拠付き関係と不明点→K3 |
| K3 推論・採否 | 関係・直接証拠・目的条件 | 推論結果と仮説の分離、適用範囲と不足評価、主張の採否 | 採用可能な意味・未成立理由→K4/K5/K6 |
| K4 ネイティブ言語計算 | 目的、原子的意味/関係、出力制約、文脈 | 六要素に基づく新しい意味内容計画と表層系列の計算 | 新しいContentPlan候補・実文面→K7 |
| K5 記憶→推論→適応 | 版付き観測、成否、実証済み変換、反例、旧記憶 | 証明を保つ既存変換の合成、または観測起点の仮説形成。別の入力へ条件付き適応し、反例/依存変更で失効 | Memory/LearningRecord・後続計算結果→K2/K3/K4/K6 |
| K6 目的・行動・状態 | 元Goal、必要成果、許可、予算、結果 | 生産→消費の依存計画、停止/取消/再開、権限内の実要求、単一状態更新 | ActionRecord・CaseRevision・必要な出力/接続依頼→K7/外部 |
| K7 内容採用・実結果照合 | K3/K4/K6の成果、出力・作用receipt | 意味採用、実結果の照合、必要成果の成否で元目的を最終判断 | 採用済みContentPlan、完了/停止/未達と履歴→出力機/次要求 |

K1→K2→K3→K4→K7は固定の実行順序ではなく、最低限成立させる実値の依存関係である。K5/K6/K7が実データを生産・消費できなければ中核完成ではない。入力機に必要な型はK1〜K7から逆算し、出力機に必要な媒体契約はK7から逆算する。

### 言語計算の六要素（既存識別子を改名しない）

1. TOKEN_SPACE＝原文と生成結果の対応を保持する有限系列集合。
2. CONTEXT_STATE＝目的・意味・根拠・履歴・出力条件を保持する有限文脈。
3. PARAMETERIZED_TRANSFORM＝版付きの非ニューラル候補変換。
4. CONDITIONAL_NEXT_TOKEN_DISTRIBUTION＝候補集合に対する条件付き次要素分布。
5. SEQUENCE_OBJECTIVE＝内容・意味・文面・長さ・停止を評価する系列目的。
6. DECODING_IF＝同一状態で同じ候補・結果へ至る有限選択規則。

六要素の型・関数・n-gramが存在するだけでは言語生成成立としない。入力側が完成した説明文を複数渡し、順序や接続句を選んだだけなら「限定編集・配列」であり、**初見意味からの新しい内容計画と文章生成**の成立ではない。入力の原子的命題と新たに構成した主張/説明内容を識別でき、依存する根拠とともにK7へ採用されること。

### 学習の成立

学習＝記憶→推論→適応。R2が許容する形成経路は二つに分かれる。

1. **証明保存型の合成**：型・変数・条件・依存根拠を確認した既存変換を新たな短縮実行経路へ合成する。全証明を回復でき、元の実行経路と重複実行せず、新規入力へ条件付き適用できる場合にPROVEN_ADOPTEDを許す。ユーザーが与えた規則も根拠と適用範囲を明示した条件付き命題として扱える。ただし、規則を受理・再生しただけでは学習ではない。
2. **観測起点の仮説**：観測例から関係/手続き候補を形成しても、初期状態はHYPOTHESIS_RETAINED。母集団・領域・独立性・誤りの損失・閾値・反例・再検証/期限を定めた事前の経験的採用契約とその検証がある場合に限り、指定範囲の予測利用へEMPIRICAL_SCOPED_ADOPTEDとできる。観測回数だけで普遍的真理・因果へ昇格しない。

いずれも学習前後で、未見の別問題における実結果・推論経路・資源の測定可能な変化を示し、領域外の反例と後の矛盾観測を扱う。中核施工中は**同じ工事用直接中核経路**で比較し、三機通電後は**同じ通常利用者入力経路**で再実証する。前者の成立を後者の成立へ流用しない。依存の失効、原本、旧判断、新判断を記録する。単なる記憶追加、定型解答の再生、模型版の変化のみでは学習成立としない。

## 05 中核施工の七つの**成立ゲート**

ゲート＝試験数でなく**必要な現実の演算とデータ依存が成立したか**を判定する機械的な述語。工事用の直接型付き入力と非判断性の観測治具は許容するが、実際のK1〜K7の内部演算を迂回してはならない。テストの名前・実行成功・記録の有無はゲートPASSを意味しない。**中核施工ゲート`CORE-G01`〜`CORE-G07`は施工専用ID。R2の既存要求`C01`〜`C13`（外部根拠系）と別名前空間であり、互いの受入や実績を混同しない。**

| ゲート | 入力・処理に対する成立述語 | 明示的な失格例 |
|---|---|---|
| CORE-G01 主語・条件 | 初見の異なる主体、否定、時刻、適用範囲を与え、実内部状態・導出と帰属を保持。前提修正で依存結論が更新 | 出力文中の文字列一致だけ |
| CORE-G02 関係・推論 | 複数の新しい前提を統合し、結論・反事実・矛盾・不足を根拠IDと実依存で区別 | 定型応答、根拠のない正答 |
| CORE-G03 意味・文章生成 | **完成文でない原子的意味/関係条件**から中核自身が新たな説明/比較/短文の内容計画を組み、六要素の計算により実文面を作りK7が採用。生成された各内容と元根拠を照合 | 完成済み文の並べ替え、接続句付与のみ、外部生成、read-only別APIだけでK7未接続 |
| CORE-G04 記憶・後続利用 | 実際の中核計算結果を版付きで記憶し、次要求が同値を再読して利用、訂正は新しい版を作る | 定数回答の再表示、保存しただけ |
| CORE-G05 推論から適応 | R2の**証明保存型合成**または**観測起点の仮説形成**を内在的に実行。型/根拠/採用範囲を守り、同じ**直接中核経路**で学習前後を対照、未見の別問題へ実際に適応し結果/経路が変化。領域外例・矛盾観測で旧採用を適切に撤回。通常入口はT02で再実証 | 宣言済み規則の単純再生、根拠検証のない合成、学習前後の差がない、採用契約のない仮説を事実化、反例後も旧結論を採用 |
| CORE-G06 停止・行動・目的 | 元Goalと必須成果の対応を保持し、権限/資源/取消/効果不明/未達で偽COMMITしない。再開は版と依存を持つ | 停止状態を正機能の成功に算入 |
| CORE-G07 再現性 | 同一意味・記憶・模型・資料版・時系列で実演算と採用結果が一致し、版変更による差を説明 | テスト出力のみ一致、外部条件無視 |

ゲート証拠の必須形＝要求述語→原入力（新規例）→実producer→中間値・版・依存根拠→実consumer→生成結果→採否・停止→成立判定。各ゲートの状態は PASS / PARTIAL / FAIL / NOT_RUN / BLOCKED_AUTHORITY / UNKNOWN のいずれか。PASS以外は工程の成立ではない。七件全てPASSの場合に限って「中核施工成立」を宣言し次工程へ移る。途中の失敗は本来のK領域まで戻し、専門能力・入力機の増築に逃がさない。

- B14は宣言済み二規則の合成と別主体への適用・失効。**R2の証明保存型合成に該当し得る正規の学習経路**として評価する。ただし同一の**工事用直接中核経路**での学習前後比較、領域外反例、後続矛盾の全ゲート証拠が揃ったか未確認であり、B14のテストPASSだけでCORE-G05の全面PASSへ流用しない。現状判定＝PARTIAL（再観測待ち）。通常利用者経路の学習前後比較は三機接続後のT02で別途判定。観測起点の仮説形成はR2の別経路として保持するが、CORE-G05に両経路の同時PASSを無根拠に強制しない。

## 06 入力機・出力機の**施工範囲の閉じ方**

**入力機の先行完成は「一般言語解析の全対応」ではない。** CORE-G01〜CORE-G07で成立した中核が要求する最小の実運転入力を、既存契約上の通常入口から封印し渡せれば三機接続工程へ進む。最低限、①中核の初見意味・文章要求、②記憶/学習後の追問、③曖昧/不正/権限欠落に対する保留が、原文・出所・版・主語・目的を保持して通ること。日本語の代表的な正常/異常入力で確かめる。英語・省略・複合資料・全表記揺れ等の追加対応は93要件の全体系施工で漏れなく接続する。**入力機の一般文法全般を先に完成させることを三機接続の前提にしない。**

**出力機の先行完成も「全媒体対応」ではない。** K7が採用した初見文章、訂正/学習結果、目的の不足・停止を、まずCLIまたは既存HTTPの少なくとも一つの通常入口から実バイトとして出し、文字/意味の不変とRenderObservationを中核へ返すこと。必要作用の実確認・不明・失敗を型付きで返す。CLI/HTTP両方、PDF/画像/音声/ブラウザ等の全入口・全媒体は後続全体系で接続する。出力機が文章内容を新規創出/採否してはならない。

三機の施工成立＝通常の公開入口で **(T1)新しい説明文の実表示、(T2)学習を別問題へ適用した結果の実表示、(T3)実描画・許可作用の観測を中核が元Goalと照合する経路** がいずれも実行されたこと。正常ケースだけでなく停止/未達も一ケースとして観測する。すべて同一の中核所有状態・版を通る。コードや型だけの接続、定型挨拶、通電した旨の報告だけでは不成立。

## 07 全体系の躯体・品質・受入の分離

### 躯体を先に完成する

三機実経路が成立したら、数学/統計、表・文書・コード、外部資料取得/検索、引用、比較/論説、複数段目標、媒体/配送、再開/訂正/取消など、必要な全専門接続口を配置し、93要件と発見要件の通常経路を**全数実装・接続**する。各要件には「原入力→実作用→証拠・中間値→次consumer→実成果/失敗→元Goal」を対応させる。安全上必要な局所停止機構は施工中から備える。外部の実認可/環境だけが不足する場合、その対象だけをBLOCKED_AUTHORITYとして保留し、内部の施工欠落を権限不足と偽らない。未実装の必須正機能がある間は「全体系躯体完成」としない。

### QCは躯体完成後

構成・入力意味・全相互作用・異常・権限・予算・停止/復旧・版・旧互換・資源・性能・OS/ABI/形式の適合を、完成候補を固定して体系的に検査する。欠陥は責任機械へ戻し、修正前後の同条件の証拠を残す。施工中の限定構文/型/煙試験をQCの代替にしない。

### QAはQC後

R2が定義する初見一般質問24件、文章12件、会話10組（各4〜6ターン）、意味変換30件、全系12シナリオ、反証22項目、全93要件＋発見要件を、対象版/母集団/環境/期待値の分離を保持して独立評価。GPQA Diamondは198問全件、正式LIVE限定、seed=0、独立並列継承と同一中核逐次学習を区別、各90分、採点正解の遮断、原データ照合値41d1213cd7a4998605a26c2798500652572007161b3a92817ba46b35befcd305を保持。既存の参照対象（Europe PMC / Crossref / 英語Wikipedia、OpenAlex無効）は正式条件と照合。旧40/198等の別構成結果は現行Rustの成績でない。中核単体と専門能力利用時、LIVEとreplay、旧βと新Rust、仮想適合と実機観測を混合しない。

## 08 施工中の制御と資源

- 工事中の小単位確認＝構文、型、変更で影響する実接続、限定smoke、権限/秘密/破壊/再送/状態破損に直結する安全試験。小単位ごとに全suite・Clippy・全workspace build・全OS・長時間QAを機械的に反復しない。ただし既存の契約上必須の安全ゲートを消さない。
- 同じ境界の入力spanや文法分岐の改善が続いても、新しい実consumerへ必要な前提を満たした時点で下流へ進む。さらに改善が必要なものは要件として保持して全体系施工に繰り入れる。根因が中核なら中核へ戻る。
- OS保証は対象規格と仮想で適合確認。Windowsを優先し8GB条件を検証対象とする。未測定のOS/CPU/実機を保証済みと宣言しない。実機は原則、定めた仕様への確認であり仕様の場当たり的変更根拠にしない。
- 権限外の外部送信/書込、二重不可逆作用、秘密流出、未知の再送は該当経路を停止。権限が不要な独立施工は継続する。
- 過去の監査不備と訂正は、生成原因/適用範囲/変更前後を保存する。過去の事実を新しい成功へ言い換えない。
- BUILDの成果指標＝**元目的に向かい実際のどのproducerからどのconsumerへ値が流れたか**。局所記録やテスト数ではない。

## 09 施工状態の公開的表示

状態を次のように分離する：CODE_PRESENT → CORE_WIRED → CORE_GATES_PASSED → THREE_MACHINE_WIRED → SYSTEM_SHAPED → QC_SCOPED_PASS → QA_SCOPED_RESULT → OWNER_RELEASE_DECISION。前状態は次状態を自動保証しない。すべての状態に対象Git版・環境・母集団・証拠・未成立条件を保持する。要求台帳のUNVERIFIEDをPASSに読み替えない。百分率は分母と判定条件が実際に固定・監査された場合だけ提示する。

**本仕様の終端条件＝中核七ゲートの実成立→必要最小の入力/出力→三機の実通路→全93要件を含む全体系躯体→体系的QC→独立QA。各条件を成立させる演算・証拠が無いときは偽の合格・偽の完成を禁ずる。**
