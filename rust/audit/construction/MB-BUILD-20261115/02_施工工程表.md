## 0. 最上位の順序・工程判定規則

施工依存：**基線再確認 → 唯一中核の実装 → 中核七ゲートの実成立 → 必要最小の入力機 → 必要最小の出力機 → 三機の実経路 → 専門能力と93要件を含む全体系躯体 → QC → QA**。

前五段は全体系BUILDの内部依存関係である。中核施工時の小さな通電確認と、全体系の体系的QCは別物。各局所で全suite・全部品検査・形式的承認を回して工程を止めない。逆に必要ゲートがFAIL/PARTIALなのに「試験だけPASS」で次へ移ることも禁ずる。**次工程への移行は、明記した成立述語と実証拠によってのみ行う。**

作業者は工程の完了条件を「コードを書いた」「テストを作った」「テストが通った」「報告を保存した」「Gitに反映した」のいずれにも置換してはならない。判定の対象は、実際に要求された値・推論・結果・帰還が同じ責任主体の実経路で成立したか。

### ゲート状態

| 状態 | 意味 | 次工程移行 |
|---|---|---|
| PASS | 当該工程の**全成立述語**について実行版・原入力・実中間値・消費先・結果が対応している | 許可 |
| PARTIAL | 一部の下位機能だけ成立。残る必要な述語が未成立 | 不可 |
| FAIL | 実結果が成立述語と矛盾 | 不可。原因工程へ復帰 |
| NOT_RUN | 実演算・実接続を確認していない | 不可 |
| BLOCKED_AUTHORITY | 特定の外部権限により実作用だけが停止 | 独立施工は続行。関連経路の成立宣言は不可 |
| UNKNOWN | 観測不能で理由と対象を限定できていない | 不可。必要な観測を行う |

原本・実装・試験ログの事実を更新する場合、観測時点/HEADを保持し、旧報告は書き換えず訂正記録を追加する。NOT_RUNやPARTIALを「失敗が観測されなかったからPASS」に変換しない。

## 工程1：唯一中核の契約・実処理を一度に組む

主語＝中核。目的＝K1〜K7を一つの本体で生産→消費させること。**入力機/出力機の便利な設計から逆算して中核を縮小しない。**

### 1A 中核の型・責務・状態

1. 直接の型付き意味・出所・条件・否定・権限・元Goalを受ける工事用入力口を決める。通常の自然文解析はこの工程の条件にしない。
2. 既存RequestEnvelope/MeaningIR/InputBundle、GoalContract/CaseRevision、Relation/LearningRecord、ContentPlan/OutputEnvelope、RenderObservation/DeliveryReceiptをR2へ照合。変更する場合は旧契約と意味対応・保存互換・影響を示す。
3. 唯一の中核が、原目的→必要成果の依存→意味と関係→推論/採否→生成/学習→内容計画採用→観測/停止/完了を同じcase・versionで辿れる実データ経路を施工する。
4. K1〜K7の各実演算にproducerとconsumerを割り当てる。既存の関数を流用可。新しい独立判断者・独立学習器・独立状態更新器を作らない。

### 1B 非ニューラル内容・文章生成

1. Layer0六契約 TOKEN_SPACE / CONTEXT_STATE / PARAMETERIZED_TRANSFORM / CONDITIONAL_NEXT_TOKEN_DISTRIBUTION / SEQUENCE_OBJECTIVE / DECODING_IF を実演算として内部接続。
2. 入力として、**完成済み文章ではない**原子的意味・命題・関係・出所と、説明/比較/短文などの作業目的・表現制約を与える。
3. 中核自身が新しい内容計画（説明で何を主張し何の根拠を使うか）を作成し、系列生成し、K7が内容を採用する。出力治具は純粋に記録するだけで、意味決定を行わない。
4. 出所にない事実を生成したら採用を止める。固定した質問文に固定した答えを貼り付ける実装、入力された完成文の連結だけで成果と呼ぶ実装を許さない。

### 1C 観測・推論・学習の循環

1. 元観測を不変で記憶し、仮説の成立条件と導出を版管理する。
2. R2の二経路を分離する。証明保存型は型/条件/変数/証拠を照合して既存の変換を合成し、証明を保つ短縮経路として採用可能。観測起点の仮説は推論候補を形成しても、事前の経験的採用契約（母集団/独立標本/誤りの帰結/閾値/適用範囲/反例/期限）と実証がない限り非権威の仮説のままとする。
3. いずれかの適法な学習経路について、まず同じ工事用の**直接中核経路**でbefore/afterを比較し、未見の別対象/別条件の結果または推論経路・資源が実際に変化することを記録する。通常利用者経路によるbefore/afterは入力機・出力機接続後のT02で実施する。
4. 領域外の例と後から生じた矛盾・反例で依存する採用を失効し、当時の原文・旧判断・新判断の両方を保持する。
5. ユーザーが宣言した規則の合成も、実際の採用経路と新規適用・帰還まで示せば証明保存型学習として認め得る。単なる規則の記録・再生は学習でない。観測起点の仮説の全面実装と証明保存型のゲート成立を混同しない。

### 1D 目的・実結果・停止

1. 元Goalから必要成果・条件・禁止作用・権限・予算・期限の依存を作る。
2. 有効な結果を次の処理が消費することを確認し、単なる進捗カウンタ更新によるCOMMITを禁止。
3. 許可不足、必要成果欠落、取消、効果不明、資源限界、未解決矛盾で実際に停止または保留する。履歴・状態版・後続再開条件を保持。
4. 出力機未完成時は非判断性の観測治具で仮の描画receiptを再現してよい。ただし現実の出力機/媒体の成立とは別状態とする。

工程1終了述語＝K1〜K7の実機能が相互に値を消費し、工事用の型付き入力から中核内の採用/状態まで実演算で通る。型や関数の定義だけ、ユニット試験だけでは終了しない。

## 工程2：中核七ゲートの有界な直接施工確認

目的＝工事用直接入力によって本体の必要能力が実際に存在することを確認。これは全体系QCでも独立QAでもない。

本工程の`CORE-G01`〜`CORE-G07`は**施工ゲート専用ID**。R2の93件に含まれる要求`C01`〜`C13`は**検索・外部根拠系の別ID**であり、ゲート結果を要求台帳に同名転記しない。

| ゲート | 直接与える初見条件 | 合格に必要な実producer→consumer→結果 | 不合格の具体例 |
|---|---|---|---|
| CORE-G01 | 初見の主体・否定・条件・時間変更 | 型付き入力→K1→K2/K3→採否、訂正前後の実結果差 | 表面の語が一致しただけ |
| CORE-G02 | 複数前提と未成立条件、矛盾/反事実 | K2が関係/根拠を構成→K3が導出/仮説/停止を区別 | 既成答えの選択 |
| CORE-G03 | 原子的意味・関係と初見説明/比較/短文目的 | K3の意味→K4が**新内容計画と新文面**を形成→K7が採用、元根拠へ追跡 | 入力済み完成文の順序変更・接続句のみ、K7未接続 |
| CORE-G04 | 実計算、次要求、前提訂正 | K6/K5の版付き記憶→後続K2/K3の消費→更新結果 | 保存した件数だけの証明 |
| CORE-G05 | 根拠付き既存変換の合成、または観測列からの仮説形成。別の未見事例、領域外例、後続矛盾 | K5がR2の正規採用規則を適用→**工事用直接中核経路**で学習前後を比較→未見実結果/経路が変化→反例で依存失効。通常入口はT02 | 条件不検証の合成、単なる記録/再生、無契約の経験的昇格、前後差なし |
| CORE-G06 | 権限外、有限資源、取消、効果不明、元目的未達 | K6/K7が必要な実結果を識別→偽成功せず停止/再開 | 拒否できたことを正機能完了と呼称 |
| CORE-G07 | 同一入力・記憶・模型・資料版、版変更 | 実演算/生成/採否/履歴の再現、版変更差の因果 | 実装条件が違うのに同一性を主張 |

中核検査には、新規意味・未知語・未知主体・新しい条件を持つ工事用例を使用する。期待値/採点正解を中核模型・記憶に入れない。同一入力と出力だけでなく中間根拠・選択・採用・停止も記録する。CORE-G03/CORE-G05は他ゲートの成功では補えない。

**工程2終了述語＝CORE-G01〜CORE-G07がそれぞれPASS。七件のテスト報告が存在することではない。** 一件でもPARTIAL/FAIL/NOT_RUNなら工程3へ移行不可。対象のK領域へ戻って施工を再開する。できない部分を入力機・外部専門機能・固定回答で代替してはならない。R2自体の設計衝突なら根拠と影響を示して設計者/オーナーへ上流差戻しする。

## 工程3：中核に必要な入力機を最小実経路へ接続

目的＝中核の型に実原文を供給する。**ここではあらゆる自然文法の完成を要求しない。**

1. K1〜K7が実際に要求した元主体・目的・関係・根拠・時刻・条件・権限・未解決等に対し、既存のinput.rsと凍結入力系の有用部分を再利用する。
2. 代表的な日本語の初見説明・比較入力、記憶からの追問/訂正入力、曖昧/否定/権限不足の入力を、原文・source span・版を保持して封印する。
3. 入力機は中核へ必要な意味を渡すが採否しない。未知文法は勝手に推論した命令へ変換せず保留とし、詳細対応を全要件施工の未完として残す。
4. 英語、半角カナ、NFKC、原文証拠、複文、省略、長文、資料別出所などの既存対応を壊さない。ただし中核が要求した最小の原文実経路が通った後も、その精密化だけを先行して連続させない。

終了述語＝公開入力→一回の封印→中核の必要入力→実中核判断が、最低限の代表ケースで成立し、未解決は正しく停止する。**全言語一般文法への対応は工程6の全数要件で回収する。**

## 工程4：中核の採用内容から出力機を最小実経路へ接続

目的＝K7の採用内容を現実の文字/成果物に変え、結果をK7へ返す。

1. 既存のRenderer/OutputEnvelope等を中核の採用版に接続する。出力機で説明の意味・新事実・結論を作らない。
2. 最小実経路はCLIまたは既存HTTPのいずれかで、実文字列・出力bytes/hash・RenderObservationとエラーを記録する。次工程で双方の通常入口を接続。
3. 許可された作用だけ行い、未配信/試行/確定/不明/失敗を区別する。実効果を得ていない場合、形式的receiptを合成してCOMMITを許さない。
4. 文書・画像・音声・外部配送の網羅は全体系躯体へ回す。安全・権限の境界を捨てない。

終了述語＝採用した意味と実出力が対応し、観測・失敗が中核の元Goalへ戻る。単なる文字列整形やHTTP 200だけでは不可。

## 工程5：三機の通常経路を一本通電

目的＝中核の内在能力を利用者入口から実利用できるようにする。**ここが全体系施工の最初の横断通電地点。**

次の三つを通常入力→入力機→中核→出力機→中核結果照合の一本の経路で実演する。

- T01：未知の意味条件を持つ利用者原文から、**中核が新しい内容/文章**を生成・採用し、実表示され、その描画観測が元Goalへ戻る。
- T02：先に入力された観測を記憶→推論→適応した結果が、別の未見の要求の答えを変え、利用者に実表示される。反例のある場合は旧採用を失効する。
- T03：実描画/実作用のCONFIRMED、未達/UNKNOWN、取消/停止を区別し、中核が元目的に照らして適切にCOMMITまたは非完了を出す。

役割を跨ぐ依存関係を確認する。CLI・HTTP等の入口の単なる成功応答、テンプレ挨拶、ハードコードされた正答、未接続の別テストAPIは無効。R2の意味制約・作用制約・版を維持。

終了述語＝T01/T02/T03全件PASSで三機通常通電。どれか失敗すれば中核/入力機/出力機の生成根因へ戻る。補修後に三件の関連経路を確認し、不要な全suiteはここで繰り返さない。

## 工程6：専門接続口と93要件の**全体系躯体**

目的＝三機の骨格に、旧能力と全要件を一度で配置し、全利用者経路が動く機械とする。ここでは局所ごとに全品質検査を行わない。

1. R2の要件登録を保持し、A01〜A15（言語/意味）、B01〜B13（課題/成果）、C01〜C13（根拠/外部情報）、CAP-D01〜CAP-D14（記憶/学習）、E01〜E12（目的/状態）、F01〜F14（入口/媒体）、G01〜G12（保証/実証）を漏らさず各通常経路へ配線する。追加発見要件は新識別子を付ける。
2. 旧ソース416識別と重複除外360経路を保持/置換/未適用/未確認に分類して、必要な機能を後継コードで接続する。313選定回帰は独立の歴史的集合。
3. CLI、HTTP、ブラウザ、会話、複数利用者、記憶・再起動、入力媒体、出力媒体、許可された送達とその失敗経路を一つのCoreへ収束させる。
4. 数学・表/文書/コード・検索/引用・論説・翻訳/音声/画像等の専門演算は、必要な外部値だけ提供するポートとして接続。根拠資料の実本文と検索結果一覧を別証拠とする。外部能力を中核自身の性能へ算入しない。
5. 全要件の行を「入口/元目的/producer/実中間値/consumer/成果/receipt/中核の終端/不足理由」へ写像し、実装・通電を進める。接続がない要件は未完成として残す。
6. R2全系12シナリオ・22反証の経路を施工。正機能は動く実演算で実装し、禁止/不明経路には早期の停止を設ける。
7. Windows優先8GB、標準的Windows/Linux/macOSの規格と仮想環境による適合を構築契約に反映。全OS実機での物理確認を全体系施工の着手条件にしない。対象規格の未観測を保証済みと呼ばない。

終了述語＝実機能を持つ全体系が通常入口から各必須成果・失敗・帰還へ接続され、実装欠落がないこと。権限待ちだけは対象の外部作用を限定して記録。単なる抽象ポートや停止を正機能の代替にしない。ここで完成候補の版と全要件の施工状態を固定してQCへ送る。

## 工程7：全体系完成後のQC

目的＝完成躯体の品質欠陥を正常/異常/相互作用で検出し、上流へ帰還する。

- 対象版と全要求・全入口・各媒体/OS/性能条件・分母を固定する。構文、型、Rust fmt/check/Clippy、workspace全テスト、build、CLI/HTTP実起動、関連OSの仮想適合を同じ版で記録。
- 主語/目的/条件/否定/引用/根拠保存、七中核機能、言語/学習、通常入口、外部作用と出力帰還を検査。
- 二重受理、同時書込み、CaseRevision衝突、actor越境、秘密、外部資料内の偽命令、版不整合、再起動、取消、未知外部効果、二重送達、復元、CPU/RSS/8GB、予算/時間限界を検査。
- 元Python成果とRust成果の同値性/退行は実行した対照で判定。過去のPASSを新RustのPASSへ転記しない。
- 欠陥は中核/入力/出力/専門ポート/実作用の原因工程へ戻し、修正前後の原文・条件・証拠・再試験を履歴に保持する。整合した全体系版へ再結合してからQC再判定する。

終了述語＝QC範囲、合否、改修/再試験、残余欠陥、NOT_RUN、対象版が特定された。未実行を合格に変換しない。

## 工程8：独立QAと保証範囲の閉包

目的＝QCが対象とした現物について、利用者が引き受け得る保証範囲を独立に観測する。

1. 初見一般問24、文章生成12、会話10組×4〜6ターン、意味変換30、全系12シナリオ、反証22、93要件＋発見要件を事前固定の評価条件で実測。評価正解・採点情報・将来問題を模型・記憶・Core推論から隔離。
2. GPQA Diamond198問全件のLIVE評価は、原データ照合値、seed=0、各90分、独立並列継承と同一中核逐次学習の差、採点正解遮断、資料参照対象と時点を既存正式契約どおりに守る。固定packet replayをLIVE結果にしない。
3. 中核単体/専門機能付き、旧Python/現Rust、OS/CPU、CLI/HTTP/ブラウザ、仮想/実機、Cloud Run/ローカル、配布方法、性能/8GBを別保証対象として扱う。
4. QA_SCOPED / QA_NOT_ESTABLISHED / OUT_OF_SCOPE、未実行/失敗/保留を明示し、期待に満たない条件を黙って母集団から削らない。
5. 公開、正式リリース、提供先・費用・保証範囲の採用はオーナーによる**別判断**。QAが完了しても自動デプロイ/外部送信しない。

終了述語＝確かな現物・母集団・環境・適用範囲について成立/不成立/未観測とその根拠が明確。

## BUILD_BATCHの運用法

BUILD_BATCH＝完成物を次consumerへ進める一束。依存工程の完了条件を置換する単位ではない。

1. 各束の最初に「目的/現在ゲート/実際の不足/今回のproducer/次consumer/必要な変更/安全境界」を確定。
2. **少なくともどの新しい実値がどのconsumerへ渡ったか**を成果として報告。型追加、span精度、検証数、文書化しか変わらないときは、それが現在の未通電経路を塞ぐ具体的根因か証明する。
3. 同じ局所の改善が連続するときは、三機通常通電/全体系のどの成立述語を妨げるかを再判定。通電を阻害しない改善は後続の全数要件へ残して次consumerへ進む。個別分野の完全仕上げを先に目的化しない。
4. BUILD中の検証は構文/型/変更した接続のsmokeと必須安全確認に限定。全suite/全OS/長時間ベンチ/重い品質票はQC/QAへ送る。必要な既存契約ゲートは回避しない。
5. 施工の各意味ある束でGitの版と未完を保存することは許可範囲に従うが、「毎小片ごとのcommit/pushを工程完了条件」にしない。途中記録は必要最小で足り、品質工程の詳細ログを先取りしない。
6. 非自明な理論/設計衝突だけを根拠とともにオーナーへ差し戻す。実装上の普通の修復、観測、試験に逐次承認を要求せず、既に許可された施工を自律継続する。

### 一束の記録項目（必要な値だけ）

現在HEAD/工程/ゲートとその状態、元目的、契約・要求ID、変更した実producer、実consumer、実入力/中間/出力と版、実確認結果、安全/権限境界、旧機能への影響、残るFAIL/PARTIAL/NOT_RUN、次の接続。実際に取得しない欄はUNKNOWNまたはNOT_RUN。詳細な機械的全資産棚卸し・全suite報告を一束の成立条件にしない。

**本工程表の停止条件＝（a）中核七ゲート未成立で入力工程に進もうとした時、（b）三機未接続で専門機能の増築へ移ろうとした時、（c）正機能未接続のままQC/QA合格を宣言しようとした時、（d）権限外・秘密/破壊/二重不可逆作用の恐れがある時。停止するのは当該逸脱または危険作用であり、許可済みの独立施工の全停止ではない。**
